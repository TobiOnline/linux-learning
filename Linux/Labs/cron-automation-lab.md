# Cron Automation Lab

## Objective

Configure and validate a Cron job that automatically executes a Bash backup script.

## Environment

- Ubuntu 26.04 LTS
- WSL2
- Host: ODYSSEY
- User: olawo
- Cron managed by systemd

## Scenario

Important data stored in `/home/olawo/important-data` needs to be backed up automatically.

A Bash script creates timestamped compressed archives and stores them in `/home/olawo/backups`.

Cron is used to execute the script automatically.

## Source Data

The test source directory contained:

- `customers.txt`
- `app-config.txt`
- `audit.txt`

## Backup Script

The backup script is stored at:

`/home/olawo/DevSecOps/linux-learning/scripts/backup.sh`

The script:

- Defines the source directory
- Defines the backup destination
- Generates a timestamp
- Creates a compressed `.tar.gz` archive
- Records successful execution in a log file

## Manual Validation

The script was made executable and tested manually before being scheduled.

A successful manual execution created:

`backup-2026-08-27_15-41-23.tar.gz`

The archive contents were inspected using:

`tar -tzf`

The archive contained all three source files.

## Cron Configuration

For testing, the script was temporarily scheduled to run every minute:

`* * * * * /home/olawo/DevSecOps/linux-learning/scripts/backup.sh`

The every-minute schedule was used only to verify the automation without waiting for a production-style schedule.

## Expected Result

Cron should execute the backup script without manual intervention and create additional timestamped backup archives.

## Actual Result

Cron successfully executed the script automatically.

It created new backups including:

- `backup-2026-08-27_15-45-01.tar.gz`
- `backup-2026-08-27_15-46-01.tar.gz`

The backup log also recorded successful executions.

## Cron Verification

Cron activity was inspected using:

`journalctl -u cron`

The journal showed:

`(olawo) CMD (/home/olawo/DevSecOps/linux-learning/scripts/backup.sh)`

This confirmed that Cron executed the script rather than the backups being created manually.

## File Ownership and Permissions

The automatically generated files were owned by:

`olawo:olawo`

An interesting difference was observed between the manually generated and Cron-generated backups.

Manual backup permissions:

`-rw-r--r--`

Cron-generated backup permissions:

`-rw-rw-r--`

This demonstrated that scheduled processes may execute with a different environment or `umask` from an interactive shell.

## Problems and Observations

### Tar Absolute Path Warning

During execution, `tar` displayed:

`Removing leading '/' from member names`

This occurred because the source directory was specified using an absolute path.

Tar removed the leading slash from paths stored inside the archive.

### Cron Mail Output

The Cron journal also reported:

`No MTA installed, discarding output`

The backup itself still completed successfully.

Cron captured output generated by the command but the WSL environment did not have a Mail Transfer Agent configured to deliver that output.

## Security Considerations

- The scheduled job ran as the normal `olawo` user rather than root.
- The backup script was owned by `olawo`.
- No credentials or secrets were stored in the crontab.
- An absolute script path was used in the Cron configuration.
- The temporary every-minute Cron job was removed after testing.
- Production backup automation should include retention and disk-space monitoring.
- Scheduled jobs should only receive the privileges they actually require.

## Cleanup

After validating the automation, the every-minute Cron entry was removed.

`crontab -l` was used afterward to verify that no active test job remained.

## Lessons Learned

- Cron can automate recurring Linux administration tasks.
- Scripts should be tested manually before being scheduled.
- Cron's execution environment may differ from an interactive shell.
- `journalctl` can be used to verify whether Cron executed a scheduled job.
- File ownership and permissions should be checked after automated execution.
- Scheduled jobs should follow the principle of least privilege.
- Temporary Cron jobs should be removed after testing.
